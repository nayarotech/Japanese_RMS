# K. Future implementation order

Each phase ends with working, tested software. Security and tenant-isolation tests are written **with** each
module, not afterwards. No phase starts without approval.

| Phase          | Scope                                                                                                                                                                                                                                                                                                                                                                           | Exit criteria                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **0**          | Architecture, scaffolding, docs (**this phase**)                                                                                                                                                                                                                                                                                                                                | Approved architecture and decisions                                                                               |
| **1**          | Platform foundation: install runtime deps, `packages/config`, logger, error model, Express app + health + graceful shutdown, DB pool + Kysely + migration runner, `withTenantTransaction`, outbox table + writer, worker runtime skeleton (job runner + outbox relay), Socket.IO + Redis adapter wiring (no business events), CI with PG/Redis service containers, image builds | API, worker and web containers build and run. Health checks pass. Integration-test harness works with RLS enabled |
| **2**          | `identity` (sessions, password, MFA, recovery, rate limits), `authorization` (permission catalog, roles, AccessContext), `tenants`, `restaurants` (locations), `audit`, `staff`                                                                                                                                                                                                 | Cross-tenant suite running. AuthZ matrix tests. Privileged actions audited                                        |
| **3**          | `subscriptions` + `entitlements` (registry, plans/versions, resolution, overrides, caching, enforcement helpers), minimal platform-admin UI for plans and onboarding, `branding` (brand + domain resolution, web theming, metadata)                                                                                                                                             | `requireFeature` used by every later module. White-label pages render per domain. Brand-leak CI on                |
| **4**          | `menus`, `tables` (table sessions), POS device registration                                                                                                                                                                                                                                                                                                                     | Restaurant admin can configure a location end-to-end                                                              |
| **5**          | `orders` (idempotency, snapshots, totals, concurrency), real-time location events + client reconciliation, POS UI                                                                                                                                                                                                                                                               | Concurrency tests (parallel edits, duplicate submits) pass. Multi-replica WS test passes                          |
| **6**          | `payments` (checkout, split/partial if approved, refunds with step-up), receipts (Japanese format, pending tax/invoice spec)                                                                                                                                                                                                                                                    | Financial invariants tested. Double-checkout impossible. Audit complete                                           |
| **7**          | `reporting` (business-day sales, exports via worker), `notifications` (branded, localized email)                                                                                                                                                                                                                                                                                | Report correctness tests against fixture data. Export isolation tests                                             |
| **8**          | `qr-ordering` (QR menu, then QR ordering)                                                                                                                                                                                                                                                                                                                                       | Anonymous-session abuse tests, rate limits, entitlement gating                                                    |
| **9**          | `online-orders` (pickup, then delivery)                                                                                                                                                                                                                                                                                                                                         | Personal-data handling reviewed against partner-approved privacy requirements                                     |
| **10**         | `integrations` (HotPepper, Google reviews, … as approved), partner subscription sync, developer-fee reconciliation module                                                                                                                                                                                                                                                       | Signed and idempotent webhooks, reconciliation reports                                                            |
| **Pre-launch** | Load tests at pilot scale, external penetration test, ASVS L2 review, backup restore drill, incident runbooks, monitoring and alerts                                                                                                                                                                                                                                            | Go-live checklist signed off                                                                                      |

Why this order: identity, authorization and tenant isolation underpin everything, so mistakes there are the most
expensive. Entitlements must exist **before** feature modules so that no module is built without its gate.
POS (menus → orders → payments) is the core value for every plan. Channels (QR, online) and integrations reuse
the order pipeline and come after it is proven.
